# 11 Nov 2026 — SeQUeNCe, using MUERP as the example

**SeQUeNCe** (Simulator of QUantum Network Communication), PyPI `sequence` 1.3.1. Discrete-event simulator: a timeline fires device and protocol events in simulated time. It does **not** include Zeng et al.’s Algorithms 1–4. Those run in Python first; SeQUeNCe then tries to *execute* the resulting tree.

Running example throughout: Zeng et al., *Multi-user Entanglement Routing Design over Quantum Internets* (ICDCS 2024). Three users (Alice, Bob, Carol) and one switch \(S\) — their Fig. 4a. MUERP wants an **entanglement tree** (here: Alice–\(S\)–Bob and Alice–\(S\)–Carol), 2 exclusive qubits per channel at a switch, and a one-slot success probability \(P\).

---

## How a run is wired

1. **Graph → routers.** NetworkX (or JSON) becomes `RouterNetTopo`. Every vertex is a `QuantumRouter`. Mid-link `BSMNode`s are extra hardware for photon generation, not MUERP switches. Tag MUERP users vs switches by **name** and **memory size**.
2. **Paths.** Overwrite each router’s **forwarding table** with the next hop from Algorithm 1–4. `RequestApp.start` has no path argument.
3. **Book memories (RSVP).** Each pairwise channel is one `RequestApp`. Intermediates reserve **2×** `memory_size`. Overlap is refused (`MemoryTimeCard`). This is MUERP Def. 3.
4. **Advance the timeline.** After \(t=1\,\mathrm{s}\), entanglement generation and swapping run for a service window. SeQUeNCe counts pairs (`memory_counter`). That is **throughput**, not Zeng et al.’s slot \(P\).
5. **\(P\) outside.** Rejected reservation \(\Rightarrow P=0\). Else multiply \(p\) and \(q\) (Eq. 1–2) in a script. SeQUeNCe has no metric named \(P\).

## Features (what it actually provides)

| Feature | What it is | MUERP example |
|---|---|---|
| **Discrete-event kernel** | `Timeline` schedules messages, photon arrival, memory expiry. Attempts are sequential in simulated time, not one simultaneous slot. | Zeng et al. assume every hop and swap in one slot. SeQUeNCe approximates admission by stopping the timeline *before* the service window, then computing \(P\) from the reserved tree. |
| **Topology** | `generate_config` / `RouterNetTopo`. Templates include linear, star, Waxman. No separate User class; `sq.Switch` is optics. | Fig. 4a = four `QuantumRouter`s. Waxman 10 users + 50 switches is a 60-node NX graph with roles tagged by `memo_size`. |
| **Quantum memories** | `memo_size` → `MemoryArray`. Coherence time and cutoff can expire pairs. | \(Q_S=4\) admits both Fig. 4a channels; \(Q_S=2\) admits one and **rejects** the second. |
| **RSVP** | End-to-end reservation along the forwarding-table path. Exclusive time slots on memories. | The MUERP “can this tree fit?” question. RSVP still **chooses which memory indices**; Algorithms 1–4 only choose paths. |
| **Static routing** | Next-hop tables, not a built-in MUERP solver. | Pin Alg. 4’s next hops (and reverse) so RSVP follows Alice–\(S\)–Bob and Alice–\(S\)–Carol. |
| **RequestApp** | Pairwise session: initiator asks for `memo_size` pairs to a responder over `[start, end]`. | One app per tree edge. Two starts on the same Alice app overwrite `reservation_result`; use `accepted_reservations` on the switch. Reverse the second initiator if needed. |
| **Link generation** | Single-heralded (or Barrett–Kok) EG on `QuantumChannel`. Loss is **dB/m**, not \(p=\exp(-\alpha L)\). | Convert \(\alpha,L\) to attenuation, or compute \(p\) after admission. Mid-link BSM is **not** Zeng et al.’s \(q\). |
| **Swapping** | `swapping_success_prob` on `EntanglementSwappingA/B` = paper \(q\). Default is **1**, not 0.9. Formalism must match the quantum manager (`bell_diagonal` for this stack). | Set \(q=0.9\). Two swaps on Fig. 4a (one per length-2 channel) enter Eq. (1) as \(q^{\ell-1}\). |
| **Fidelity / decoherence** | EG/ES events carry fidelity; short `coherence_time` + cutoff kills waiting pairs. | Named MUERP extension, not in Zeng et al.’s plotted \(P\). On Fig. 4a, generation fidelity ~0.90, swapping ~0.57; cutoff on → 0 delivered pairs. |
| **Many reservations on one pool** | RSVP holds several trees on the same `MemoryArray`. | Second named extension: two 5-user groups sharing one \(Q_r\). |
| **Logging** | Protocol events, `memory_counter`, expired memories. | Use for throughput and fidelity. Do not treat pair counts as Eq. (2). |

## Two numbers (do not mix)

- **Slot \(P\)** (Zeng et al.): one try of the whole tree. Fig. 4a with \(p=q=0.9\): \(P=(p^2 q)^2=0.531441\) if both channels are reserved, else \(0\).
- **SeQUeNCe throughput:** how many pairs `RequestApp` collected in 0.2 s of retries (e.g. 7 and 10 on Fig. 4a). Different question.

---

## One-sentence summary

SeQUeNCe is a timed reservation + device stack: it can **host** MUERP admission (exclusive \(Q_r\), follow pinned paths, refuse overflow) on Fig. 4a and at 10+50 nodes; Algorithms 1–4 and Eq. (1)–(2) stay in Python beside it.

## Algorithms 1–4 (Zeng et al., offline; not inside SeQUeNCe)

Python in `Meetings/algorithm{1–4}_*.py`. They output an entanglement tree (paths + Eq. (2) \(P\)). SeQUeNCe only follows the next hops.

**Algorithm 1 — maximum-rate channel.** One pair of users \(u_i,u_j\). Dijkstra with edge weight \(\alpha L - \ln q\) (log of Eq. (1), so a *product* of hop success and swaps becomes a *sum*). Skip a neighbor switch if it has fewer than 2 qubits left. Recover the path from the `Prev` array. RATE \(= q^{\ell-1}\prod_i p_{i,i+1}\) with \(p=\exp(-\alpha L)\). Building block for 2–4.

**Algorithm 2 — optimal when capacity is plentiful.** Assumes \(Q_r \ge 2|U|\) on every switch (Theorem 3), so capacity is ignored. Run Alg. 1 for every user pair; sort those channels by RATE descending; Kruskal / union-find: add a channel only if the two users are not already connected. Output: \(|U|-1\) channels, \(P=\) product of RATEs. Optimal *only* under that \(Q_r\) bound. On Fig. 4a it still returns two channels even if \(Q_S=2\) (infeasible in hardware).

**Algorithm 3 — conflict-free (finite \(Q_r\)).** Input: the all-pair Alg. 1 channels from Alg. 2, plus leftover \(Q_r\). Walk them best-RATE first; keep a channel only if every switch on it still has \(\ge 2\) qubits; subtract 2 per switch; union-find as in Alg. 2. If users remain in several components, repeatedly run Alg. 1 between users in different unions under the *remaining* \(Q_r\) and add the single best feasible channel. If none exists, terminate, \(P=0\). Fig. 4a: \(Q_S=4\) \(\Rightarrow P=0.531441\); \(Q_S=2\) \(\Rightarrow P=0\).

**Algorithm 4 — Prim-based (finite \(Q_r\), no Alg. 2).** Pick a start user \(u_0\). \(U_1=\{u_0\}\), \(U_2=U\setminus\{u_0\}\). For \(|U|-1\) rounds: among all Alg. 1 channels from someone in \(U_1\) to someone in \(U_2\) that still fit leftover \(Q_r\), take the max RATE; move that outer user into \(U_1\); subtract 2 qubits per switch on the path. If a round finds nothing, terminate, \(P=0\). Same Fig. 4a numbers as Alg. 3 on that tiny graph; can differ from Alg. 3 when \(Q_r\) is tight on larger graphs.
